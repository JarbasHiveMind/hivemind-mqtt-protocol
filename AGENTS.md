# AGENTS.md — `hivemind-mqtt-protocol`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

An MQTT broker-mediated network protocol plugin for
[hivemind-core](https://github.com/JarbasHiveMind/hivemind-core). Satellites and
the hub both connect as ordinary clients to an MQTT broker they may already use
for sensors (Home Assistant, ESPHome, Tasmota, ESP32); the encrypted
`HiveMessage` frame is carried unchanged inside the MQTT payload, the same frame
the WebSocket transport sends, so the hub needs no inbound port. Part of the
[HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol for
connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). Related repos:
[hivemind-plugin-manager](https://github.com/JarbasHiveMind/hivemind-plugin-manager)
(loads this plugin by entry point),
[hivemind-websocket-protocol](https://github.com/JarbasHiveMind/hivemind-websocket-protocol)
(the default transport and the source for the transport-plugin authoring
pattern), [hivemind-bus-client](https://github.com/JarbasHiveMind/hivemind-bus-client)
(satellite-side client library).

## Layout / build / test

- Package module: `hivemind_mqtt_protocol/` (single-file plugin, `__init__.py`).
  Tests live in `tests/` (`test_mqtt_protocol.py` unit tests, `tests/e2e/`
  end-to-end) — do not create a second test directory.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[e2e]" --prerelease=allow`
- Run the suite in the foreground: `python3 -m pytest tests/ -q`.
  `tests/test_mqtt_protocol.py` mocks the paho client and `hm_protocol`.
  `tests/e2e/` drives a real `HiveMindMqttProtocol` master and a real
  `HiveMindSlaveProtocol` satellite over an in-process MQTT broker double
  (`tests/e2e/broker.py`) — no external mosquitto instance or network needed.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is a
  bug to FIX at the source, not to work around with a pin downgrade.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- This plugin registers under the `hivemind.network.protocol` entry-point group
  as `hivemind-mqtt-plugin`, loaded by `hivemind-plugin-manager`'s
  `NetworkProtocolFactory` at runtime. Do not rename the entry point or change
  its constructor signature without checking every consumer.
- Wire back-compat is law: the MQTT payload carries the same `HiveMessage` frame
  the WebSocket transport uses, and the topic scheme
  (`<prefix>/<api_key>/{in,out,status}`) is part of the deployed contract for
  every satellite already wired to a broker. Do not change topic shape, QoS
  defaults, or frame encoding in a way that breaks a satellite that hasn't
  upgraded.
- ACL/auth field parity with the WebSocket transport is real here, not
  aspirational: `_build_client_connection` in `hivemind_mqtt_protocol/__init__.py`
  copies `allowed_types`, `can_broadcast`, `can_propagate`, `can_escalate`,
  `is_admin`, and `crypto_key` from the client-DB record onto the connection,
  the same set the WebSocket path sets. Any new ACL field added to
  `HiveMindClientConnection` upstream must be mirrored here too, or MQTT peers
  silently get looser or stricter permissions than WebSocket peers with the
  same key.
- An unknown `api_key` in the topic must fail fast: `_build_client_connection`
  calls `handle_invalid_key_connected` and returns `None` without creating a
  peer entry. Keep it that way — never fall back to a default identity or a
  partial connection for an unrecognized key.
- Never add a new bus message type. Extend an existing message's payload
  instead.
- Audio/binary frames are homelab-only by design (QoS 0, fire-and-forget) —
  do not add reliability guarantees to that path that assume a WAN-grade
  broker.
